# AnimeLoader

Расширение для Chromium-браузеров (Chrome, Edge, Opera, Яндекс), которое скачивает серии
с двух сайтов:

| Сайт | Плееры |
|---|---|
| [YummyAnime](https://old.yummyani.me) | **Kodik**, **Alloha**, **CVH** |
| [AnimeGO](https://animego.me) | **Kodik**, **CVH**, **AniBoom** |

Возможности:

- диапазон серий «от — до» (для фильма или одиночной серии диапазон скрыт);
- выбор плеера, озвучки и качества (максимальное / 1080p / 720p / 480p / 360p);
- куда сохранять: в любую папку (системный диалог, папка запоминается) или в «Загрузки»
  браузера — тогда после загрузки есть кнопка «Открыть папку»; галочка
  «Создать папку с названием тайтла»;
- готовый `.mp4` на выходе без перекодирования: CVH отдаёт обычный файл MP4, Alloha — fMP4
  (сегменты склеиваются как есть), AniBoom — fMP4 с отдельной дорожкой звука (дорожки
  сводятся в один файл), Kodik — MPEG-TS, его библиотека mux.js перепаковывает в MP4
  (в настройках можно выбрать сохранение `.ts` как есть);
- уже скачанные серии пропускаются, поэтому прерванную загрузку можно просто запустить заново;
- пауза и остановка, прогресс по серии и в целом;
- «Отладочная информация»: время, серии, сегменты, объём, скорость, текущий темп, журнал с копированием.

## Установка

1. Откройте `chrome://extensions` (в Edge — `edge://extensions`).
2. Включите «Режим разработчика».
3. «Загрузить распакованное расширение» → выберите папку `AnimeLoader`.

## Как пользоваться

1. Откройте страницу аниме, например
   `https://old.yummyani.me/catalog/item/cugai-zagrobnogo-mira` или
   `https://animego.me/anime/ledyanaya-stena-2-3814`.
2. Нажмите на значок расширения: откроется отдельное окно загрузчика. Это окно, а не
   всплывающая панель, поэтому загрузка не прервётся при переключении вкладок.
   Не закрывайте окно, пока идёт загрузка.
3. Выберите плеер, озвучку, качество, серии и папку → «Скачать».

Файлы называются `Название - 01 [Озвучка].mp4`.

## Как это устроено

**Сайты.** YummyAnime отдаёт всё через JSON API: `GET /api/anime/{slug}` и
`/api/anime/{id}/videos`. AnimeGO — через разметку плеера: `GET /player/{id}` (список серий),
`/player/videos/{серия}` (плееры и озвучки серии); без заголовка `X-Requested-With` сервер
отвечает 404. На AnimeGO список плееров запрашивается по каждой серии, поэтому у длинных
сериалов окно открывается на несколько секунд дольше.

| Плеер | Ссылка на поток | Поток | Заголовки | Ограничения |
|---|---|---|---|---|
| Kodik | страница плеера → `POST /ftor` (адрес берётся из JS плеера) → ссылки, зашифрованные сдвигом букв + base64 | HLS, MPEG-TS, до 720p | `Referer` сайта | не замечены |
| Alloha | плеер грузится в скрытом iframe, `content/alloha-hook.js` перехватывает ответ `/bnsi/movies/{id}` | HLS, fMP4, до 1080p, зеркала `url1 or url2` | `Origin: https://alloha.yani.tv` (без него 403 `origin_mismatch`) | ~40 сегментов на ссылку, дальше 403 `session_blocked` |
| CVH | `plapi.cdnvideohub.com`: плейлист тайтла (`/player/sv/playlist?pub&id&aggr`) → `/player/sv/video/{vkId}` | обычный MP4 на CDN ok.ru, до 1080p (бывает 4K); качается кусками по 8 МБ | `Origin: https://player.cdnvideohub.com` (с Origin расширения CDN отвечает 400) | ссылки привязаны к IP пользователя |
| AniBoom | страница `aniboom.one/embed/…` (только с `Referer` сайта) → JSON в `data-parameters` | HLS, fMP4, видео и звук отдельными плейлистами, до 1080p | `Referer` сайта для страницы плеера | не замечены |

**Почему Alloha через скрытый плеер.** Запрос ссылки подписывается одноразовым заголовком,
который вычисляет обфусцированный JS плеера. Повторить его снаружи ненадёжно, поэтому
расширение открывает настоящий плеер (с `autoplay=1`) и забирает его ответ.

**Лимит скорости Alloha.** Замеры показали, что лимит считается на одну ссылку: примерно
40 сегментов можно взять сразу, дальше — около одного раз в 4 секунды, иначе ссылка
блокируется (403 `session_blocked`). Поэтому загрузчик берёт новую ссылку каждые
30 сегментов: серия 720p (~530 МБ) скачивается примерно за минуту без блокировок.
Если блокировка всё же случилась, загрузчик снижает темп, ждёт (3, 6, 10, 15 минут)
и продолжает с того же сегмента.

**Защита от 403 за частые запросы** (общая для всех плееров, темп настраивается для каждого):

- темп: число одновременных запросов и пауза между ними, пауза между сериями;
- смена ссылки каждые N сегментов (нужно Alloha: у неё лимит на ссылку);
- 403 с причиной `session_blocked`/`limit` — темп снижается вдвое, пауза 3 → 6 → 10 → 15 минут,
  затем загрузка продолжается с того же сегмента; после серии удачных запросов темп
  постепенно возвращается;
- 429 — замедление и повтор (с учётом `Retry-After`);
- 403/404 без причины — ссылка считается устаревшей и запрашивается новая; если и новая
  сразу отвечает так же, это считается блокировкой (см. выше).

**Куки.** Сегменты, плейлисты и ключи запрашиваются с куками браузера для домена CDN
(`credentials: 'include'`). Служебные запросы к плеерам (страница Kodik, API CVH, страница
AniBoom) — без кук: им нужен только правильный `Referer`/`Origin`. Alloha открывается
настоящим плеером в скрытом iframe, и куки он ставит и использует сам, как при просмотре.

**Подстановка заголовков.** `fetch()` не позволяет задать `Referer`/`Origin`, поэтому
окно загрузчика добавляет сессионные правила `declarativeNetRequest`, ограниченные
своей вкладкой: обычный просмотр сайтов они не затрагивают.

**CVH: файл по частям.** Ссылка CVH ведёт на обычный MP4. Загрузчик узнаёт размер
(`Range: bytes=0-0`) и качает файл кусками по 8 МБ в несколько потоков тем же механизмом,
что и сегменты HLS: с повторами, записью по порядку и обновлением ссылки, если она устарела.
Серия 1080p (~400 МБ) скачивается за 10–20 секунд.

**AniBoom: сведение дорожек.** Видео и звук приходят отдельными fMP4-плейлистами, у обоих
track_ID = 1. Сегменты дорожек качаются вперемешку по времени, а `js/fmp4-merge.js` собирает
общий init-сегмент (две дорожки, track_ID 1 и 2) и переписывает номера дорожек и фрагментов
в каждом `moof`. Сами данные не меняются.

**Запись на диск.** Через File System Access API файл пишется потоком и появляется
под своим именем только после окончания записи, недокачанных файлов в папке не остаётся.
Открыть такую папку в Проводнике браузер не даёт (API не сообщает даже её путь), поэтому
есть второй режим — «Загрузки» браузера: файл собирается в Blob (браузер держит его на
диске, а не в памяти) и сохраняется через `chrome.downloads`; кнопка «Открыть папку»
вызывает `chrome.downloads.show`. Уже скачанные серии в этом режиме находятся по
истории загрузок и пропускаются.
Перепаковка TS → MP4 делается одним проходом после загрузки серии (при поэтапной
mux.js дублирует кадры на стыках сегментов), поэтому на время перепаковки серия
Kodik 720p занимает в памяти около 300–600 МБ. Если памяти мало, выберите в
настройках формат TS. В конце в MP4 прописывается длительность, иначе часть
плееров её не видит.

## Структура

```
manifest.json           MV3
background.js           клик по значку → окно загрузчика
downloader.html         окно загрузчика
content/alloha-hook.js  перехват ссылки в плеере Alloha (мир MAIN, только в iframe загрузчика)
js/app.js               интерфейс и очередь серий
js/sites/index.js       выбор сайта по адресу страницы
js/sites/yummy.js       API YummyAnime
js/sites/animego.js     разметка плеера AnimeGO
js/providers/index.js   плеер → функция получения ссылок
js/providers/kodik.js   ссылки Kodik
js/providers/alloha.js  ссылки Alloha (скрытый iframe)
js/providers/cvh.js     ссылки CVH (API cdnvideohub)
js/providers/aniboom.js ссылки AniBoom
js/hls-download.js      загрузка HLS и файлов по частям: темп, повторы, смена ссылок, запись по порядку
js/playlist.js          разбор m3u8 (m3u8-parser), отдельный звук, нарезка файла на части
js/fmp4-merge.js        сведение дорожек видео и звука fMP4
js/pacer.js             ограничение темпа запросов
js/output.js            запись в папку или «Загрузки», TS → MP4 (mux.js)
js/mp4-fix.js           длительность в init-сегменте MP4
js/net-rules.js         заголовки через declarativeNetRequest
js/settings.js          настройки и запомненная папка
lib/                    mux.js 7.1.0, m3u8-parser 7.2.0 (Apache-2.0)
tests/                  тесты
```

## Тесты

```bash
npm test
```

Модульные тесты: расшифровка Kodik, разбор страниц YummyAnime и AnimeGO, плейлисты CVH и
AniBoom, группировка серий, темп, загрузка HLS с имитацией CDN (порядок записи, устаревшие
ссылки, блокировка, смена ссылки, остановка), загрузка файла по частям, сведение дорожек fMP4.

Живая проверка одной серии из Node (без браузера; Alloha так не проверить):

```bash
node tests/live-episode.mjs https://animego.me/anime/ledyanaya-stena-2-3814 aniboom 1 episode AniLiberty 720
```

Сквозной тест в настоящем Chrome: расширение ставится во временный профиль, серия
скачивается в OPFS (вместо системного диалога выбора папки), затем файл проверяется
воспроизведением и перемоткой:

```bash
npm install
npm run e2e -- --player alloha --dub AniLibria --from 9 --to 9 --quality 720
npm run e2e -- --url https://animego.me/anime/ledyanaya-stena-2-3814 --player cvh --dub "SHIZA Project" --from 1 --to 3
```

## Ограничения

- Firefox пока не поддерживается: нет `showDirectoryPicker`, а фон MV3 в Firefox
  устроен иначе. Код записи в «Загрузки» для этого случая уже есть (`DownloadsTarget`).
- Плеер Aksor (YummyAnime) пока не поддерживается: на момент проверки его сервер
  `player.aksor.tv` отвечал 502, и разобрать, как он отдаёт видео, было нельзя.
- DASH-потоки не поддерживаются (у AniBoom есть и HLS, он и используется).
- Сайты и плееры меняются: если загрузка перестала работать, журнал в «Отладочной
  информации» покажет, на каком шаге ошибка.
